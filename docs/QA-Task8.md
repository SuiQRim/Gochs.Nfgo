## Smoke test

1. Запустить `dotnet build`.
2. Запустить `dotnet run`.
3. Открыть web UI.
4. Проверить Dashboard.
5. Открыть карточку каждого формирования.
6. Создать новое формирование.
7. Создать подразделение внутри него.
8. Добавить сотрудника.
9. Добавить групповое имущество без инвентарного номера и количеством больше 1.
10. Добавить индивидуальную технику с инвентарным номером и количеством 1.
11. Проверить фильтры сотрудников и техники.
12. Создать оповещение.
13. Перевести оповещение из Created в Sent или Failed.
14. Убедиться, что повторное изменение завершённого оповещения запрещено.

## Негативные сценарии

- [ ] пустое/пробельное обязательное название → 400;
- [ ] несуществующий FormationId/UnitId → 404;
- [ ] повторный PersonnelNumber → 409;
- [ ] повторный InventoryNumber → 409;
- [ ] InventoryNumber + Quantity > 1 → 400;
- [ ] Quantity <= 0 → 400;
- [ ] удаление Formation с Units → 409;
- [ ] удаление Formation с Notifications → 409;
- [ ] удаление Unit с Employees → 409;
- [ ] удаление Unit с Equipment → 409;
- [ ] Created → Created для Notification → 409;
- [ ] Sent/Failed → другой статус → 409.

## Ожидаемые демонстрационные показатели на новой пустой БД

Seed специально содержит разные статусы для демонстрации Dashboard. Точные значения могут изменяться после CRUD-операций пользователя.

## Граница задания

Реальная доставка оповещений внешними каналами не входит в задачу. В системе ведётся регистрация сообщения и его статуса.
